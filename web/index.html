Microsoft Endpoint Check

Checks from your browser which Microsoft endpoints for Intune, Windows Update, Autopatch and Defender are reachable. Live sources are preferred, with automatic fallback to generated data.

Run the full check locally with PowerShell

The browser can only send HTTP requests. For TCP, latency and download tests through the client's real proxy and firewall path, run the PowerShell script on the affected device. It does not change any settings on the device. 

powershell.exe -ExecutionPolicy Bypass -Command "& .\CheckMicrosoftEndpointsV2.ps1 -Services Intune,Defender,WindowsUpdate -HtmlReport .\Microsoft-Endpoints.html -OpenReport"
Download CheckMicrosoftEndpointsV2.ps1 Intune only: CheckMEMEndpoints.ps1 All options on GitHub

Run it from the folder you saved it to. Use -Services All for every service; without -Services the script shows an interactive menu. Works with Windows PowerShell 5.1 and PowerShell 7 (also macOS and Linux).

Notes

  • Browser checks do not replace TCP/ICMP tests.
  • HTTP status does not matter; any response within timeout counts as reachable.
  • If CORS issues occur, a no-cors fallback is attempted.

Proxy/firewall guidance

Multiple endpoints are unreachable. Check proxy exceptions and firewall rules for the affected services (especially 443/TCP).
